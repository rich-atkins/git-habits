# git-habits v0.2 — evidence floors and the sabotage self-test

v0.2 changes no metric definitions. It changes what the tool is willing to *say*, and adds proof that it catches what it claims to catch.

## Why (the short version)

Two incidents, same lesson. First, v0.1's own development produced "0% AI co-authored" when trailers were never captured — an unknown rendered as a zero. Second, watching an LLM eval gate in another project report PASS on **zero judgments** — because zero judgments contained zero failures. A gate that can't fail isn't a gate, and a report that cannot say "not enough evidence" will eventually lie. v0.2 generalises both into the tool's spine.

## 1. Evidence floors (fail closed on thin data)

Every rate now knows its denominator and a floor below which it refuses to be a number:

| Floor | Default | Governs |
|---|---|---|
| `--min-evidence-commits` | 5 | lines/commit (mean/p50/p90), commits/active day, AI co-authored % |
| `--min-evidence-lines` | 200 | moved, legacy, rework (% and per-1k) |

Below the floor the report prints `insufficient (n=3 commits, need >=5)` **in place of the value** — an annotation, not an omission, so the reader sees *why* there is no number. Raw counts stay visible. The floors are deliberately low bars for "a number at all", not for "a trustworthy number": the <30-commit volatility note still applies above them.

Behaviour changes that follow from the principle:

- **An empty selection is a failed measurement, not a measurement of zero.** `scan` on a selection with no commits prints one line and exits 1 — v0.1 printed a fully-formed block of fictional zeros (`0.0/active day`, `0.0%` everything) at exit 0, and even rendered the empty window as the *trailer* unknown.
- **`compare` refuses an empty window** (exit 1, naming which window) instead of printing deltas against fiction. Per-metric, a delta line whose metric is below the floor in either window prints `insufficient evidence in <side>` rather than a percentage.
- **JSON output carries a sibling `insufficient` map**; numeric fields stay numeric so downstream arithmetic keeps working.

## 2. The sabotage self-test

Nothing in v0.1 proved the tool would actually flag a regime change — or stay quiet without one. v0.2's test suite builds **real git repositories** on every run:

- **PLANTED** — commit size jumps ~6x after 2026-04-13, cadence rises, AI co-author trailers appear. `compare` must show the shift; `detect` must find the month **unaided**.
- **CONTROL** — the same shape throughout. `compare` must stay quiet.

Both directions are asserted, because a detector that always fires is as broken as one that never does. Run it yourself: `pytest tests/test_sabotage.py -v`.

## Compatibility

- Exit codes: `scan` on an empty selection and `compare` with an empty window now return 1 (previously 0). Scripts that relied on exit 0 with zero-filled output should treat the new exit 1 as the correction it is.
- JSON: new `insufficient` key; existing keys unchanged.
- Metric values, thresholds and exclusion rules: unchanged.
