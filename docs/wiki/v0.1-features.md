# git-habits v0.1 — what it measures, and how to read it

git-habits computes coding-habit signals from git history alone: commit metadata and
numstat line counts. It never reads file contents, so it is safe to run against
employer or client repositories — nothing sensitive can leave the machine, because
nothing sensitive is ever loaded.

## Commands

| Command | Question it answers |
|---|---|
| `scan` | what do the habits look like in this selection? |
| `compare --split <date>` | how did they change either side of a date (e.g. adopting AI tooling)? |
| `detect` | when did commit size shift, without being told the date? (candidate, never a finding) |

Input is a live repo (`--repo`) or a TSV export (`--from-export`) produced on a
machine you cannot clone from — both go through the same parser.

## Metrics and their denominators

Every rate is reported **per thousand changed lines AND per commit**. Per-line is
primary: it stays stable when commit granularity shifts, which is exactly what
happens when a team changes how it works.

| Metric | Denominator | What it suggests |
|---|---|---|
| moved (reuse) % / per-1k | changed lines | code being relocated rather than re-typed — refactoring |
| legacy touch % / per-1k | changed lines | changes landing in year-old code — maintenance depth |
| rework ≤14d % / per-1k | changed lines | changes to lines touched in the last fortnight — churn |
| lines/commit (mean, p50, p90) | commits | batch size; report the median, the mean rides on outliers |
| commits per active day | active days | cadence |
| AI co-authored % | commits | `Co-Authored-By` trailer presence — **only where trailers were captured** |

## Design positions (v0.1)

- **Exclusions on by default, and reported.** Lockfiles, build output, vendored code
  and generated files are excluded, and the report says how much was removed —
  a run that silently drops 60% of lines has an invisible thumb on the scale.
- **Unknown is not zero.** A source that never captured commit trailers reports
  AI co-authorship as *"not captured by this source (unknown, not zero)"*, never 0%.
  This rule exists because v0.1's own development produced the wrong number first.
- **Validity notes in the output, not the docs.** Short history, young-repo legacy
  suppression, missing rename detection and small samples are called out inline.
- `detect` refuses to run on fewer than four qualifying months — the only hard
  refusal in v0.1, and the seed of what v0.2 generalises.

## What it cannot tell you

Quality, intent, or authorship of ideas; content-level signals (duplication,
error-masking — see the companion tool diff-habits); anything about repositories
whose history was squashed or imported. The README's "what this tool cannot tell
you" section is the honest boundary; every entry on it has already produced a
wrong number during the tool's own development.
